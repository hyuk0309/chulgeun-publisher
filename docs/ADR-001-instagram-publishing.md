# ADR-001 인스타그램 캐러셀 자동 게시 방식

- 상태: 게시 경로·토큰 부분은 [ADR-002](ADR-002-facebook-login.md)로 대체됨 (2026-11-07). 이미지 공개 URL·예약 실행·언어·안전장치는 그대로 유효
- 근거 자료: `../research/instagram-auto-upload.md` §1, §5, §6, §7 (reading-ideation 기준 경로)
- 결정자: 대표님(방식 선택), 에이전트(구현 세부)

## 결정

| 항목 | 선택 | 버린 대안과 이유 |
|---|---|---|
| 게시 경로 | Meta 공식 Instagram API, **Instagram 로그인 방식**(graph.instagram.com, 권한 `instagram_business_basic` + `instagram_business_content_publish`), 개발 모드 + 본인 계정을 Instagram 테스터로 등록 | Facebook 로그인 방식: 페이지 연결이 필요해 익명 운영의 관리 대상이 늘어남. instagrapi·브라우저 자동화: 약관 위반 소지, 정지 위험. Buffer: 사람이 매주 업로드해야 함(대안으로 유지) |
| 이미지 공개 URL | GitHub 공개 저장소 + GitHub Pages(브랜치 배포, `/queue/<slug>/NN.jpg`) | R2·Supabase: 별도 가입과 결제수단·비활성 정지 문제. 비공개 저장소 Pages: 유료 |
| 예약 실행 | GitHub Actions cron(UTC). 월·수·금 07:17 KST + 09:17 KST 백업 실행 | 맥 cron: 맥이 꺼지면 실패. Claude 예약 작업: 프리뷰 단계, 결과 확인 보조로만 |
| 언어 | Python 3.9+ 표준 라이브러리만(urllib, json, unittest). 외부 패키지 0개 | Node: 맥에 설치돼 있지 않음. requests 등: 설치 단계가 늘고 공급망 위험 |
| 이미지 변환 | 맥 기본 `sips`(PNG → JPEG 품질 90, 1080x1350 그대로, 크기가 다르면 오류) | Pillow: 의존성 추가. 자동 리사이즈: 디자인이 깨져도 모르고 올라갈 수 있음 |
| API 버전 | 기본 `v27.0`(2026-11-07 공식 문서 예시), 저장소 변수 `IG_API_VERSION`으로 교체 | 버전 생략: 가장 오래된 버전으로 처리돼 예측이 어려움 |

## 안전장치(중복·오게시 방지)

1. **승인 게이트**: 큐 항목은 `approved: false`로 만들어진다. 대표님 확인 뒤에만 `queue_tool.py approve`. 캡션·이미지·시각이 바뀌면 승인이 자동 해제된다. 시리즈 문서의 "게시는 대표님이 직접 누르는가 [승인 필요]" 항목을 이 승인으로 대신한다.
2. **중복 게시 방지 3중**: (a) `posted.json`이 있으면 API를 부르지도 않음 (b) 게시 전 계정 최근 게시물 10개의 캡션과 비교해 같으면 기록만 남김(기록 커밋이 실패한 경우 대비) (c) `media_publish` 응답이 끊기면 다시 누르지 않고 계정에서 실제 게시 여부부터 확인. 워크플로는 `concurrency`로 동시에 하나만 돈다.
3. **POST는 자동 재시도하지 않음**(GET만 재시도). 컨테이너 상태가 `FINISHED`가 아니면 게시하지 않는다(폴링: 공식 권장대로 5분 이내).
4. **한 번에 1건**: 밀린 항목이 여러 개여도 오래된 것 1건만. 예약 시각에서 20시간 넘게 밀린 항목은 자동으로 올리지 않고 실패 알림(수동 실행으로만).
5. 이미지 URL을 HEAD로 먼저 확인해 Pages 미배포 상태에서 컨테이너를 만들지 않는다.
6. 토큰은 로그·예외 메시지에서 가리고, 갱신된 토큰은 임시 파일 → `gh secret set` 으로만 전달한다.

## 결과와 감수하는 점

- 저장소가 공개라 **승인 전·게시 전의 캡션과 이미지가 누구에게나 보인다.** 경로를 숨겨도 저장소 자체가 공개이므로 의미가 없어 숨기지 않았다. 미리 공개되면 안 되는 글은 큐에 넣지 않는다.
- 커밋 작성자 이메일이 공개된다. 운영용 GitHub 계정의 noreply 주소로 커밋해야 익명이 유지된다(SETUP.md 7단계).
- 토큰 자동 갱신에는 Secret 쓰기 권한이 있는 세분화 PAT(`GH_SECRETS_PAT`)가 필요하다. 이 PAT도 만료(최대 약 1년)가 있어 1년에 한 번 사람이 갱신한다.
- 장기 토큰 갱신이 8주 이상 실패하면 만료되어 대표님이 다시 로그인해 토큰을 받아야 한다.
- 캐러셀 장수 상한은 문서(20장)와 서드파티 안내(10장)가 엇갈려 코드에서 10장으로 제한했다.
- 캐러셀 항목의 `alt_text` 지원 여부가 문서상 분명하지 않아, 거부되면 alt_text 없이 한 번 다시 만든다(경고 로그).
- Pages 용량 1GB: 1건 약 1MB(실측 8장 0.9~1.0MB) × 주 3건 → 수년 여유. 필요하면 게시된 항목 이미지 정리를 나중에 추가한다.

## 미확인(첫 실행으로 확인)

1. 개발 모드(앱 심사 없음)에서 본인 계정 게시가 2026-11 현재 정상 동작하는지 — `check` 후 첫 실제 게시로 확인.
2. 캐러셀 자식 컨테이너의 `alt_text` 반영 여부.
3. 대시보드에서 발급한 토큰이 장기(60일) 토큰인지 — 갱신 워크플로 첫 실행의 "약 N일 유효" 출력으로 확인.
